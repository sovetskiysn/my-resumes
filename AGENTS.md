# AGENTS.md

Этот файл — инструкция для ИИ-агентов (Claude Code, Codex и любых других),
работающих в этом репозитории. Он описывает, что это за репозиторий, как
устроено окружение сборки, какими командами пользоваться и каких соглашений
придерживаться при правках. Читается агентом в начале сессии; человеку он тоже
полезен как краткая карта проекта. Если что-то в репозитории изменилось —
обновляйте этот файл вместе с изменением, а не постфактум.

## О репозитории

Это **репозиторий для работы с резюме**. Здесь лежат исходники резюме на LaTeX,
собранные из них PDF, подтверждающие документы (сертификаты) и настройки, за счёт
которых сборка одинаково работает на любой машине.

Резюме — не один файл, а **набор версий под разные сценарии**. Каждая версия
живёт в своей подпапке `resumes/` и представляет собой **самостоятельный LaTeX-проект**:
один `.tex`, собираемый независимо от остальных.

## Структура

```
.
├── AGENTS.md                              # этот файл
├── .agents/                               # общая настройка агентов: плагин resume-repo, скиллы, MCP
├── .claude/settings.json                  # Claude Code: включает плагины из .agents/
├── .codex/config.toml                     # Codex: включает плагины из .agents/
├── .vscode/                               # настройки редактора и рекомендованные расширения
├── cover_letters/                         # сопроводительные письма: по папке на отклик
├── certificates/                          # PDF/PNG сертификатов (AWS Academy, Coursera, Stepik, THM)
├── docs/DECISIONS.md                      # причины решений с неочевидной ценой
├── diplomas/                              # PDF дипломов об образовании (бакалавриат, магистратура)
├── templates/                             # чистые шаблоны резюме «как у автора»
│   ├── README.md                          # что за шаблоны, лицензии, как завести версию
│   ├── jakes_resume/                      # Jake's Resume (Jake Gutierrez, MIT) — база текущих версий
│   └── nanu_rezume/                       # Rezume (Nanu Panchamurthy, MIT) — сейчас не используется
├── references/                            # чужие материалы-ориентиры, не мои и не шаблоны
│   ├── real_resumes/                      # реальные резюме других людей как образцы
│   └── guides/                            # статьи и гайды о том, как писать резюме
└── resumes/                               # по подпапке на версию резюме
    ├── ai_engineer_version/
    │   ├── Sanzhar_Sovet_resume.tex       # исходник
    │   ├── Sanzhar_Sovet_resume.pdf       # собранный PDF
    │   └── .build/                        # артефакты сборки (не коммитим)
    └── full_version/
```

**Имя `.tex` во всех папках одинаковое — `Sanzhar_Sovet_resume.tex`.** Версию
определяет папка, а не имя файла: так собранный PDF, который уходит рекрутеру,
всегда называется одинаково и правильно, без `resume_final_v3_ai.pdf`.

В `references/guides/` сохранены пособие в PDF и статьи в Markdown по инженерным,
AI/ML- и исследовательским резюме. Каталог, порядок чтения и ограничения копий —
в [`references/guides/README.md`](references/guides/README.md); источники и дата
сохранения указаны рядом с материалами. Это внешние авторские рекомендации.

## Окружение сборки: LaTeX Workshop + Docker

Сборка идёт через расширение **LaTeX Workshop** (`James-Yu.latex-workshop`,
прописано в `.vscode/extensions.json` как рекомендованное).

Локальный TeX Live ставить не нужно — LaTeX Workshop запускает компиляцию
**в Docker**:

| Настройка | Значение | Что делает |
| --- | --- | --- |
| `latex-workshop.docker.enabled` | `true` | компиляция в контейнере, а не локальным `pdflatex` |
| `latex-workshop.docker.image.latex` | `texlive/texlive:TL2025-historic` | зафиксированный образ TeX Live |
| `latex-workshop.latex.autoBuild.run` | `onSave` | пересборка при каждом сохранении `.tex` |
| `latex-workshop.view.pdf.viewer` | `tab` | PDF открывается вкладкой внутри VS Code |

Образ закреплён на `TL2025-historic` намеренно: `historic`-тег не двигается,
поэтому сборка воспроизводима. **Не меняйте тег на `latest`** без явной причины —
обоснование в [DECISIONS.md](docs/DECISIONS.md#образ-tex-live-закреплён-на-tl2025-historic).

Требование к машине: установленный и запущенный Docker. Первая сборка тянет
образ (несколько ГБ) и поэтому долгая; последующие — быстрые.

## Генерация PDF

Как собрать:

- **Из VS Code** — открыть нужный `.tex` и сохранить (autoBuild `onSave`) либо
  вызвать `LaTeX Workshop: Build LaTeX project` из палитры команд. PDF
  открывается соседней вкладкой, SyncTeX связывает клик в PDF с местом в
  исходнике.
- **Из терминала** — тем же образом Docker, чтобы результат совпадал с
  редакторским. Монтируется папка конкретной версии:

  ```bash
  docker run --rm --user "$(id -u):$(id -g)" \
    -v "$PWD/resumes/full_version":/work -w /work \
    texlive/texlive:TL2025-historic \
    latexmk -pdf -auxdir=.build -interaction=nonstopmode -synctex=1 \
    Sanzhar_Sovet_resume.tex
  ```

  `--user` обязателен: без него контейнер пишет PDF от `root`, и потом файл не
  перезаписать из редактора. `-auxdir=.build` повторяет то, что LaTeX Workshop
  делает через `auxDir`.

### Куда складываются артефакты

`latex-workshop.latex.auxDir` выставлен в `%DIR%/.build`, поэтому весь мусор
сборки (`.aux`, `.log`, `.fls`, `.fdb_latexmk`, `.out`) уходит в отдельный
`.build/` рядом с документом. **PDF и `.synctex.gz` остаются на месте** — иначе
не работают просмотрщик и SyncTeX.

`.build/` никто автоматически не чистит, и это осознанно: набор файлов там
фиксированный и перезаписывается на месте, а `.fdb_latexmk` — кеш latexmk,
благодаря которому пересборки быстрые.

`auxDir` не действует на сборки мимо LaTeX Workshop: если запустить `pdflatex`
или `latexmk` руками в каталоге с исходником, артефакты лягут рядом с `.tex`.
На этот случай в `files.exclude` перечислены маски по расширениям — они прячут
такие файлы из дерева VS Code. Из гита они исключены через `.gitignore`;
реально удалить их можно только руками — `rm -rf resumes/*/.build`.

## Версии резюме под разные use case

Одна подпапка `resumes/` = одна версия = один самостоятельный LaTeX-проект.
Обе версии сделаны на базе шаблона Jake's Resume (см. [Шаблоны](#шаблоны)).

| Папка | Назначение |
| --- | --- |
| `resumes/ai_engineer_version/` | Версия под вакансии AI/ML-инженера: обрезанная и заточенная — лишнее убрано, ML/LLM/MLOps вынесено вперёд. Одна страница. |
| `resumes/full_version/` | Полная версия: то же, что AI-версия, плюс секция Summary, оба места работы Healthcare Data Analyst и навыки по аналитике данных. Две страницы: на первой Summary и весь Experience, Publications, Skills и Education начинаются со второй (`\newpage` перед Publications). |

**Порядок секций в обеих версиях:** Summary (только в полной) → Experience →
Publications → Skills → Education. Сильнее всего резюме доказывает опыт, поэтому он
идёт сразу после шапки; публикации — следующее по весу доказательство, выше списка навыков.

**Секции Projects нет.** Рабочие проекты (ITutor для Til-Qazyna, платформа для
Samruk-Energy) описаны вложенными буллетами внутри своей должности в Experience,
опубликованные работы — в секции Publications. Projects возвращаем только для
проектов вне работы: open source, пет-проекты, хакатоны
([DECISIONS.md](docs/DECISIONS.md#рабочие-проекты--в-experience-без-секции-projects)).

**Как добавлять новую версию:** скопировать папку ближайшей существующей версии,
переименовать копию под сценарий, оставить имя `.tex` без изменений, затем резать
и переставлять содержимое. После этого **добавить строку в таблицу выше** — иначе
через полгода не вспомнить, чем версии отличаются.

**Осознанная цена такой схемы:** версии — независимые копии, общих подключаемых
кусков нет. Значит, правка общего факта (новое место работы, смена телефона,
опечатка в образовании) **вносится в каждую папку руками**. Прежде чем править
одну версию, проверьте, не касается ли правка остальных:

```bash
grep -rn "+7 705" resumes/
```

Взамен каждая версия режется как угодно свободно, не ломая соседние — ради этого
схема и выбрана ([DECISIONS.md](docs/DECISIONS.md#версии-резюме--независимые-копии)).

## Сопроводительные письма

`cover_letters/` — сопроводительные письма под конкретные вакансии. Одна папка
`<дата>_<компания>_<роль>/` = один отклик: текст вакансии в `vacancy.md`, письмо в
`Sanzhar_Sovet_cover_letter.md` и, если письмо прикладывается файлом, `.tex` и `.pdf`
под тем же именем. Отправленные письма — снимок на дату отклика, при смене контактов
их не переписывают.

Письма пишутся по скиллу `cover-letter` (`.agents/skills/cover-letter/SKILL.md`):
там порядок работы, структура, тон, LaTeX-шаблон в пару к резюме и проверка. Как и в
резюме, факты берутся только из `resumes/` и от пользователя.

## Шаблоны

`templates/` — библиотека исходных шаблонов резюме на LaTeX в том виде, в каком
их выложили авторы: без моих данных и без правок. Подробности, таблица шаблонов
и лицензии — в [`templates/README.md`](templates/README.md).

| Папка | Шаблон | Лицензия |
| --- | --- | --- |
| `templates/jakes_resume/` | [Jake's Resume](https://github.com/jakegut/resume) | MIT |
| `templates/nanu_rezume/` | [Rezume](https://github.com/nanupnch/Rezume) | MIT |

Текущие резюме в `resumes/` сделаны на базе **Jake's Resume**; Rezume сейчас не
используется.

**Шаблоны не редактируем** — они эталон. Новая версия резюме заводится копией
шаблона (или ближайшей существующей версии) в `resumes/<версия>/`, и вся правка
идёт уже там. Благодаря этому `diff` между шаблоном и версией всегда показывает
ровно мои изменения.

## Сертификаты

`certificates/` — подтверждающие документы (AWS Academy Cloud Foundations и
Machine Learning Foundations, Coursera, Stepik, TryHackMe) в PDF и PNG. Это
исходные файлы «как выдали», их не переименовывают и не редактируют. Если
резюме ссылается на сертификат — ссылайтесь на файл отсюда.

## Дипломы

`diplomas/` — дипломы об образовании и приложения к ним (транскрипты). Сейчас
это `bachelor_diploma_full.pdf` и `master_diploma_full.pdf` — бакалавриат и
магистратура Astana IT University.

Разделение с `certificates/` простое: здесь официальные документы от учебного
заведения, там — сертификаты курсов и платформ.

**Имена файлов здесь английские, слова через `_`** — содержимое сканов не
меняем, но имя приводим к латинице: кириллица и пробелы в путях ломают ссылки
из LaTeX и часть тулинга. Это осознанное отличие от `certificates/`, где файлы
лежат под выданными именами ([DECISIONS.md](docs/DECISIONS.md#латинские-имена-в-diplomas-выданные--в-certificates)).

## Настройки VS Code

Все настройки проекта лежат в `.vscode/` и коммитятся — окружение должно
подниматься одинаково у всех:

- `.vscode/settings.json` — LaTeX Workshop (Docker, образ, autoBuild, вьювер),
  `auxDir` и маски `files.exclude`, прячущие артефакты сборки из дерева файлов.
  Настройки снабжены комментариями: прежде чем менять — прочитайте их.
- `.vscode/extensions.json` — рекомендованные расширения: `James-Yu.latex-workshop`
  для сборки, `anthropic.claude-code` и `openai.chatgpt` (Codex) для агентов. VS Code
  предложит их при открытии папки.

Личные предпочтения (тема, шрифт) сюда не кладём — им место в User Settings.

## Настройка агентов

Контекст агентов — этот файл, `AGENTS.md`. Claude Code и Codex читают его сами,
отдельный `CLAUDE.md` не заводим. Имя пишется строчными буквами: `AGENTS.MD` агенты
не находят ([DECISIONS.md](docs/DECISIONS.md#agentsmd-строчными-буквами-и-без-claudemd)).

**Скиллы и MCP.** Общие для Claude Code и Codex и лежат в `.agents/` как наш плагин
`resume-repo` из локального маркетплейса `resume-agents`; там же подключён внешний
`resume-skills` (ниже). `.claude/settings.json` и `.codex/config.toml` только включают
плагины; скиллы и MCP-конфигурацию в другие места не копируем.

```text
.agents/
├── skills/                  скиллы: document-style (оформление документов), cover-letter
├── .mcp.json                MCP-серверы (сейчас пусто)
├── .claude-plugin/          манифест плагина и маркетплейс для Claude
├── .codex-plugin/           манифест плагина для Codex
└── plugins/marketplace.json маркетплейс для Codex
```

Два манифеста и два маркетплейса — потому что у Claude Code и Codex разные форматы
плагинов. Поле `skills` в `.codex-plugin/plugin.json` намеренно указывает на
несуществующую папку: иначе Codex загружает скиллы дважды — из `.agents/skills/` и из
плагина.

**Плагин `resume-skills`.** Второй плагин того же маркетплейса —
[Paramchoudhary/ResumeSkills](https://github.com/Paramchoudhary/ResumeSkills) (MIT):
22 скилла про ATS, буллеты, разбор вакансии, подгонку резюме, LinkedIn, интервью. В
репозиторий он не копируется: оба агента тянут его с GitHub в свой кеш
([DECISIONS.md](docs/DECISIONS.md#resumeskills--плагином-а-не-копией)). Правила этого
файла и свои скиллы важнее его скиллов:

- письма пишутся по нашему `cover-letter`, а не по `cover-letter-generator`;
- метрику, которую `resume-quantifier` или `resume-bullet-writer` предлагают
  «оценить», агент в резюме сам не вписывает — спрашивает у пользователя
  (см. [Соглашения](#соглашения)).

**Первая настройка.** Один раз на машину, из корня репозитория:

```bash
claude plugin marketplace add ./.agents
claude plugin install resume-repo@resume-agents --scope project
claude plugin install resume-skills@resume-agents --scope project
codex plugin marketplace add "$(pwd)"
codex plugin add resume-repo@resume-agents
codex plugin add resume-skills@resume-agents
```

Сами по `.claude/settings.json` и `.codex/config.toml` плагины не ставятся: эти файлы
только включают их. Маркетплейс агенты регистрируют в своих пользовательских
настройках, а `resume-skills` с GitHub Claude Code по настройкам проекта не скачивает.
`claude plugin marketplace add` запускайте без `--scope project`: с ним команда
запишет в `.claude/settings.json` абсолютный путь вместо `./.agents`.

`resume-skills` обновляется так: Claude Code — сам, в фоне (`autoUpdate` в
`.claude/settings.json`), Codex — повтором `codex plugin add resume-skills@resume-agents`.

**Изменения.** Скилл — правка `.agents/skills/<имя>/SKILL.md`, MCP — правка
`.agents/.mcp.json`. Claude подхватывает их после перезапуска сессии, Codex — после
`codex plugin add resume-repo@resume-agents`. В `.mcp.json` не используйте `${...}`
(Codex не раскрывает переменные) и пишите путь к проекту как `.`.

**Где что хранить.**

| Что | Где |
| --- | --- |
| Устойчивые факты о репозитории и правила | `AGENTS.md` |
| Причины решений, отвергнутые варианты, принятая цена | [`docs/DECISIONS.md`](docs/DECISIONS.md) |
| Материалы откликов: вакансия и письмо | `cover_letters/<отклик>/` |
| Черновики и планы на одну сессию | scratchpad-директория сессии |

**Память решений.** Сохраняйте в `docs/DECISIONS.md`, что выбрали, какие альтернативы
отвергли, какое неочевидное ограничение повлияло на выбор и с какими недостатками
согласились. Причину смены подхода или отката записывайте сразу, чтобы не повторить
уже проверенный неподходящий путь. Отделяйте гипотезы от принятых решений; при
пересмотре сохраняйте прежнюю причину и отмечайте, чем и почему она заменена.

`docs/DECISIONS.md` и другие документы подключайте обычной Markdown-ссылкой, а не
`@`-импортом: Codex импорты не раскрывает, а Claude Code с импортом грузил бы файл в
каждую сессию.

## Соглашения

- **Правки контента резюме делает человек.** Агент помогает с вёрсткой,
  сборкой, структурой файлов и вычиткой, но не выдумывает факты биографии:
  должности, даты, компании, достижения и цифры берутся только из того, что
  дал пользователь.
- **Персональные данные** (телефон, почта, LinkedIn) продублированы в каждой
  версии — при их смене правьте все папки сразу, иначе рекрутеру уйдёт PDF со
  старым номером.
- **Артефакты сборки не коммитим**: `.build/`, `.synctex.gz`, `.aux`, `.log`,
  `.out`, `.fls`, `.fdb_latexmk`, `.bbl`, `.blg`, `.toc` — в `.gitignore`.
  Собранные PDF резюме коммитим осознанно (ими делятся), мусор — нет.
- **Собрать все версии после правки вёрстки**: правку преамбулы или макросов
  вносят в каждую папку отдельно, а версии между собой не связаны — молчаливой
  проверки, что все собираются, не будет.
- **Версию образа TeX Live не двигаем** — см. раздел про Docker.
- **Обвязка живёт в репозитории, а не глобально**: заметки, планы и задачи по
  этому проекту держим здесь, а не в пользовательских настройках агента и не в
  глобальной авто-памяти — см. [Настройка агентов](#настройка-агентов).
- **Контекст агентов — набор зафиксированных фактов, а не рабочий блокнот.** Всё,
  что записано в `AGENTS.md`, считается актуальным и обязательным, поэтому сюда
  попадает только проверенное и устойчивое. Результаты разовых проверок, гипотезы,
  статусы, TODO и черновые планы сюда не пишутся. Изменения в контексте делаются
  осознанно, когда факт действительно изменился; устаревшие записи обновляются или
  удаляются, а не копятся рядом с новыми.
- **Не указывать ИИ-ассистентов в коммитах.** В историю не попадают трейлеры
  `Co-Authored-By: Claude`, подписи `Generated with Claude Code` и другие упоминания
  ассистента — ни в сообщениях коммитов, ни в тегах. Автор коммита — человек; если
  инструмент добавляет такой трейлер по умолчанию, его убирают до коммита.
